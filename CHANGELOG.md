# Changelog

All notable changes to this project are in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
The project is alpha: the API may change before 1.0.

## [Unreleased]

Fixes after the spikes with http4k, Koin and Ktor. Batch A: argument binding and overload selection. Batch B: declarations and function values. Batch C: nil checks, type hints, one error text.

* A property no longer wins silently over a function of the same name. `(r/routes h)` with `routes(vararg ...)` and `val H.routes` was the property; it is now an "ambiguous" error that lists both and gives the ways out (`(r/routes :list [h])` for the function, `((kt/ref X routes) h)` for the property). It is the same for a member property and a top-level function, on the static and the dynamic path.
* Trailing lambda (rule 4): when the usual binding leaves the last parameter without an argument and it takes a function (function type, `fun interface`, Java single-method interface) and has no default, the last positional argument goes to it. `(dsl/module f)` for `module(createdAtStart = false, declaration: ...)` and `(sp/.status cfg code f)` after a `vararg` now work. A call that fits by the usual binding is never changed. The error "missing required parameter" says "name it" where a positional argument cannot reach the parameter.
* A collection passed as a whole to a `vararg` chooses between overloads by its elements on the dynamic path: `(r/routes :list [h])` is no longer ambiguous when every element is a `RoutingHttpHandler`. An empty collection, or elements that fit several overloads, stay ambiguous. The selection is kept per class of the elements.
* Overloads that differ only in the parameter types of a lambda (Ktor `status`): type hints on the parameters of a `fn` literal choose (`(fn [^ApplicationCall call status] ...)`). The error now says "the parameter types of a lambda" and shows the hint as the first way out. When the receiver has a type for the compiler (also a `fn` parameter at a function type), the ambiguity is a compile error, not a run-time one.
* A call of a class var is resolved as Kotlin does (rule 3): the constructors first, then the `operator fun invoke` of the companion object and the `operator fun invoke` extensions on its `Companion` of the same package. `(h/Request h/Method.GET "/a")` works for `interface Request { companion object { operator fun invoke(...) } }`; the error was "has no public constructor: it is an interface". A constructor that fits always wins, a function that is no `operator` is not called, and `(h/.invoke h/Request ...)` still works. When neither fits, the error lists both. An `object` with an `operator fun invoke` (its own, inherited, or an extension) is callable as `(f/Foo 1)`; before, any call of an object was a compile error.
* `invoke` on a value whose class implements a Kotlin function type (rule 1, rule 6): `interface RoutingHttpHandler : HttpHandler` with `typealias HttpHandler = (Request) -> Response` inherits `operator fun invoke(p1: Request): Response`, so `(h/.invoke handler req)` works (it was "no Kotlin declaration of `.invoke` fits"), on the static and the dynamic path. A parameter is checked and adapted by its Kotlin type (a number gets its width, a Clojure function becomes a function). A suspend function type gives its result. An object of a class that the package does not know (http4k: `RoutingHttpHandler` is in another package than `core`) gets the generic `invoke` of `Function1`, without a check of the argument types.
* The class var is the receiver of an extension on a `Companion`, for a property and a function (rule 3): `(h/NoOp h/Filter)` for `val Filter.Companion.NoOp` (the error was "`receiver` is Companion but got AFn"), also `kt/set!` of a `var`, also a named companion. The Companion object itself is still accepted.
* What a `kt/reify` member returns is adapted to the declared Kotlin return type, as an argument is adapted to a parameter (rule 10): a Clojure function for a function type (also suspend, or with a receiver), a `fun interface` or a Java single-method interface, a number width, a value class. Before, a Clojure function that a member of `fun interface Filter : (HttpHandler) -> HttpHandler` returned failed later with `ClassCastException`. A value that cannot be the type, and `nil` for a type that is not nullable, is a `kt:` error that names the member. A member of a `fun interface` that extends a function type has the types of that function type, so its parameters of a function type are Clojure functions. The same holds for the function that a Clojure function returns for a Kotlin lambda whose result is a function type (it was already so); `nil` there, for a type that is not nullable, is a `kt:` error that names the function type.
* `nil` is checked against the bounds of a type parameter (rule 7). `fun <T : Any> getProperty(key: String, defaultValue: T)` takes no `nil`, as `String` does not: a `nil` literal and the dynamic path were already a `kt:` error, and a `nil` that only the run time knows (`(k/.getProperty koin "key" v)` with `v` nil) is one now too ("nil where Kotlin expects a non-null value of the type parameter `T : Any`"), not Kotlin's `NullPointerException`. It is the same for several bounds of which one is not nullable, a type parameter of a class (`Box<T : Any>.put(x: T)`) and the elements of a `vararg`. Plain `T`, `T?` and `T : Foo?` take `nil`, and so does `T` given as a nullable type with `:<>`. A `vararg xs: T` with plain `T` took no `nil` element before (the check read it as non-null); it does now. A bound that is a type parameter is as nullable as that parameter (`<T, U : T>`).
* An enum entry var has a static type (its enum class), as an `object` var had: `(r/.bind "/health" h/Method.GET)` (http4k) is a direct call with no "can't be resolved statically" warning. The string literal was never the cause: a literal has a static type in every position, the receiver too. Which declaration is chosen does not change for a call that was already static.
* A call of a Clojure function has the type of its `:tag`, as the Clojure compiler takes it: the tag of the arglist that takes this number of arguments (a variadic one included), else the tag of the var, with the class resolved as Clojure does it (`^String`, `^"[B"`, `^bytes`, `^long`, `^double`, fully qualified names). `(defn u ^String [s] ...)` then `(creq/.get client (u "/x"))` (Ktor) is a direct call; it needed `^String (u "/x")` before. The tag is a hint that you wrote: it decides between the candidates that it fits for sure (a `^CharSequence` tag chooses the `CharSequence` overload, where the class of the value would have chosen `String`), else it is an upper bound, and a wrong tag is a `kt:` error at run time, never `ClassCastException`. A macro and a function with an `:inline` expansion for that number of arguments have no tag. Also, the Clojure tags `^bytes`, `^ints`, `^objects`... on a form are classes now. The declared Kotlin return type of a nested `kt` call (a property read, a companion property, an extension) was already the static type: now there are tests.
* A class that Clojure made at run time as a `:<>` type argument (the interface of a `defprotocol`, `definterface`, `deftype`, `defrecord`, a `gen-class` that is not compiled, an earlier `kt/reify`) is a `kt:` error before the Kotlin compiler runs. The text of the compiler was "unresolved reference 'domain'.": the class is in a `DynamicClassLoader`, with no class file on the class path to read. The new error names the class, says that it was made at run time and gives the two ways out: AOT-compile the namespace that defines it and put the classes on the class path, or use an overload that takes a `KClass`. A stored bridge (AOT, disk cache) loads as before: the check runs only when the compiler is about to run (`doc/limits.md`, 9). `ckway.meta/class-file-on-classpath?` is public.
* A Kotlin function value that takes a function (`((Int) -> Int) -> String`): `nil` for the function is a `kt:` error since batch B, and it has tests now. A parameter of a nullable function type, of a nullable `fun interface`, of a Java single-method interface that is nullable, of `Any?` and of a type parameter takes `nil` as before; nothing that was legal became an error.
* A class that declares its own `invoke` and also implements a function type has ONE `invoke`: the declared one (regression of the batch B change). http4k `LensExtractor<in IN, out OUT> : (IN) -> OUT { override operator fun invoke(target: IN): OUT }` and its subclasses `Lens`, `BiDiLens`, `PathLens` gave "is ambiguous" for `(l/.invoke lens req)` since batch B; the declared `invoke` overrides the one of the function type, so the synthesized one is not added for the class, for a class between it and the function type, or for a supertype that a subclass overrides (generic classes, `suspend` function types, `fun interface`). A class with no `invoke` of its own and the generic `Function1.invoke` are as before. A function-typed parameter of a `kt/reify` member (also one that the member inherits from a function type: `Filter`) was already a Clojure function, so `(next req)` works; `(h/.invoke next req)` works too, on the dynamic path (a function type has no class, so the call has no static type and warns under `*warn-on-reflection*`).
* The result of a `suspend` function that is a value class is the object, as for a function that is not `suspend`. kotlinx.coroutines `receiveCatching(): ChannelResult<E>` gave the underlying value (`(kch/.getOrNull (kch/.receiveCatching c))` was "`this` expects ChannelResult, got String", and the internal `ChannelResult$Closed` for a closed channel). Kotlin returns the object when the call was resumed and the underlying value when it returned at once (a class over a reference type), so `kt` boxes what is not the object. `kotlin.Result`, `Duration` and `VC?` are the same; a generic result is not changed. The static type of such a call is the value class now.
* `nil` that only the run time knows at a parameter or receiver that Kotlin does not take as nullable is a `kt:` error, not Kotlin's `NullPointerException: Parameter specified as non-null is null`: `(let [v (identity nil)] (s/welcome v))` for `fun welcome(name: String)` is now "kt: (s/welcome v): nil where Kotlin expects a non-null String (the argument `name` (String))". It holds for every parameter, for the receiver of an extension and of a member, on the static path. The check is a plain `nil?` test in the expansion, with the error call only in the failing branch (no var lookup, no allocation for a value that is not nil). No check where the argument cannot be nil (a literal, a number, a Kotlin call with a non-null result, a constructor, a `fn` literal), for a nullable parameter, and for a Java-declared one. It does not look at the elements of a `vararg` of a plain type. `ckway.rt/nn-fail` is the new error function; the check for a type parameter `T : Any` (batch C) uses the same inline test now.
* The way out of the error "ambiguous: function and property" names the class var as you write it: `((kt/ref r/RoutingHandler routes) x)` (the alias of your namespace for the package of the class, else the full class name; before: the placeholder `X`), and the function way out has the alias too: `(r/routes :list ...)`.
* Unknown argument types and a trailing lambda: Ktor `(eng/embeddedServer cio/CIO (:port m) (:host m) (fn [_] nil))` selected the declaration that fits by the usual binding (`environment`, `configure`, `module`) because the types of `(:port m)` were unknown, and failed at run time with "the argument `environment` is Long 0". Before batch A the same call failed the same way (there was no trailing lambda, so the other declaration had no binding). A call that has such a candidate, with a doubt about the types of the usual one, is a dynamic call now: the values choose, and the trailing-lambda retry runs at run time. Calls with known types (a literal, `(long (:port m))`, `^String (:host m)`) and calls that fit by the usual binding for sure are as before.

## [0.1.0] - 2026-10-04

First release. Clojure calls Kotlin with `ckway.core` (alias `kt`). The 11 rules:

* Namespace: `kt/require` makes one namespace from one Kotlin package, one var for each name.
* Name and call: a function or property is a Clojure function with its receivers first; a function with a receiver has the prefix `.`.
* Class names: a class var constructs and is the receiver of companion members; an `object` or enum entry var holds the instance; nested names keep their dots.
* Arguments: positional, named (a keyword names the parameter of the next argument), Kotlin defaults, and `vararg`.
* Type arguments: `:<>` gives the type arguments, also for `inline reified` functions (compiled with the Kotlin compiler into a cached bridge).
* Functions: a Clojure function goes where Kotlin wants a function type, a `fun interface` or a Java single-method interface; a Kotlin function value is a Clojure function.
* No guess: Kotlin overload rules select the declaration; an unclear call is an error; a value is adapted only to the declared parameter type.
* Write a property: `kt/set!`.
* References: `kt/ref` is Kotlin `X::y`.
* Implement an interface: `kt/reify`.
* Data: `kt/data` gives a read-only map of the primary-constructor properties.

Also: `suspend` functions and suspend lambdas (virtual threads), value classes, a per-user bridge cache with SHA-256 checks, and AOT support.

Also in this release (the fixes of the reviews before it):

* One number rule: `kt` changes a number only when the declared Kotlin parameter type says so (`Int`, `Short`, `Byte`, `Long`, `Float`, `Double`). At `Any`, `Number` or a type parameter a Clojure integer stays a `Long`, a literal or not (before, a literal that fits `Int` became an `Int` there, which made lookups in lists and maps built in Clojure miss).
* The code that `kt` emits uses only qualified names, so a local of your code named `int`, `long`, `name`, `count`... cannot capture one.
* Overload choice: a conversion of a number that `kt` makes itself (an integer for a `Double`) is used only when no overload takes the value as it is; type arguments count in the choice of the most specific overload (`List<T>` is not a subtype of `Collection<Int>`); a type hint that you write (`^CharSequence s`) is the static type of the argument; a collection passed as a whole to a `vararg` chooses between overloads when its elements can be seen, and the error says so when they cannot.
* A member that the JVM hides, in a class that is not public (`@InlineOnly` functions of the standard library), is called through a bridge with `invokeExact`: about 8 times faster than before.
* An integer literal that is out of range for its `Int`, `Short` or `Byte` parameter is a compile-time error with the same words as the run-time check.

* A type that the library itself puts on a local (the parameters of a `fn` literal passed at a Kotlin function type, `this` and the parameters of a `kt/reify` member) is an upper bound, never "a type you wrote": `(p/eachEv xs (fn [e] (p/.pos e)))` compiles again for a subclass member or overload. Your own hint on such a parameter is still the static type.
* The bridge cache keeps its entries in its own subdirectory `bridges-v1` of the directory that is named, and deletes only what it can prove that it made: entry directories with the exact generated name and only class files and `entry.txt` in them, and `.ckway-tmp-<uuid>` temporary directories. Before, a prune could delete any old directory of the cache directory (`-Dckway.cache.dir=target` lost sibling directories and `.tmp-*` of other tools). A delete never follows a symbolic link.
* The scripts `bin/test` and `examples/run` create their cache directories with mode 700 (a group-writable directory under `umask 002` was refused, so the cache was off).
* Overload choice: the specificity rule (type arguments included) decides before the closeness of a parameter type to the class of the value, so a value from a nested call (`(p/gl (c/listOf 1))`), a literal, a local, a var as a value and the dynamic path give the same answer.
* Type hints: a hint that you write decides between the candidates that it fits for sure; when it fits none for sure but the value could (`^clojure.lang.IPersistentMap` at a `Map` parameter, `^java.util.Collection` at a `List`) it is an upper bound and the call is checked at run time; a hint that can never fit stays a compile error. A wrong hint at run time is a `kt:` error that names the call, the parameter, the declaration and the actual class (before: `ClassCastException`).
* `(m/sqrt 4)`: when every candidate would need the library's own conversion of an integer, the "ambiguous" error says so and suggests `4.0` or `(double x)`.
* `kt/reify`: one written member serves every leaf override that takes the same parameter types (`S1.get(): CharSequence` and `S2.get(): Comparable<*>` over `Src.get(): Any`), with the result checked for each; leaves with different parameter types are a compile error that says to write the member under each interface.
* `ckway.meta/own-declarations` is public; `kt/reify` no longer calls private functions of `ckway.meta`. An override that narrows the result type (`override fun get(): String` over `fun get(): Any`) is now the declaration a caller sees, so `(p/.get s)` is a `String` on the static path.
* `-Dckway.interrupt.grace.ms` is clamped (at most 24 hours; negative is 0; not a number is the default): a huge value gave `ArithmeticException` instead of `InterruptedException`.
* The interrupt flag that is set again after a cancelled call is set only on the thread of the body. A suspend call from a thread that inherited the context of the body (`future`, `bound-fn`) is a top-level call in that context with a Job that is a child of the Job of the body (`doc/limits.md`, 16).
* An override that narrows the result type has the default values of the member it overrides (Kotlin marks them on the original only): `(q/.mk (q/Far))` with `interface Src { fun mk(x: Int = 7): Any }` and `class Far : Src { override fun mk(x: Int): String }` in another package works again, runs the `$default` synthetic of the original as kotlinc does (the override's body runs), and `doc` shows `x: Int = ...`.
* A suspend call completes its own Job on every exit. A call from a child thread of a body (`future`, `pmap`) that throws before it suspends no longer leaves the Job of the body waiting for ever; a top-level call that throws no longer leaves its Job active.
* Overload choice: a numeric preference on one parameter no longer overrides a disadvantage on another with an equal reference tier (`mx(CharSequence, Int)` / `mx(String, Long)` with `(p/mx "s" 1)` is ambiguous, as in Kotlin).
* A call on an untyped receiver whose candidates are one member and its narrowing overrides (`(p/.get s)` with `interface Src { fun get(): Any }`, `StrSrc : Src { override fun get(): String }`) is a static virtual call of the most general declaration again, not the dynamic path.
* `kt/reify`: the leaves of one member are matched by JVM name and parameter types, so one form serves a Java and a Kotlin leaf.
* The bridge cache prints one line per JVM when a foreign file or directory sits on an entry name (the bridge is then not cached), and deletes a `.ckway-tmp-<uuid>` directory only when it holds class files and `entry.txt` only.
* The "ambiguous" message for numbers suggests `4.0`, `(double x)`, `(float x)`; `4.0f` is not Clojure.
* One Kotlin member is one declaration of a var, however it is reached (declared by a class of the package, inherited by a subclass in the same or another package, through several supertypes): the index reads a member once (`ckway.meta`, `declared-members`) and de-duplicates by the JVM member (declaring class, JVM name, descriptor). EVERY override has the default values of the member it overrides. `(p/.mk (p/StrSrc) 2)` with `interface Src { fun mk(x: Int = 7): Any }`, `open class StrSrc : Src { override fun mk(x: Int): String }`, `class SubSrc : StrSrc()` is no longer "ambiguous".
* A default value that an INTERFACE declares can be omitted also when the library was compiled without JVM default methods (`-jvm-default=disable`, every Kotlin before 2.2): the `$default` synthetic is then in `Iface$DefaultImpls`, and the index records the class that really has it (`(ch/.close channel)` of kotlinx.coroutines).
* A member that a class has through two unrelated supertypes (`class QC : Q1, Q2` with `run2()` in both) is one virtual call, not "ambiguous".
* Overload choice is Kotlin's most-specific rule in one place (`ckway.resolve/most-specific`), compared with `kotlinc` on 109 calls: candidates are aligned by the argument that each parameter receives (named arguments in other positions: `oo(a: Int, b: Long)` / `oo(b: Int, a: Short)` with `(p/oo :a 1 :b 2)` is ambiguous); the tie-breaks (no vararg, fewer defaults used) apply only between equally specific candidates (`s5(a: Long, b: String = "d")` / `s5(a: Int, b: CharSequence = "d", c: Int = 0)` with `(p/s5 1 "x")` is ambiguous); for an integer literal `Long` against `Short` or `Byte` is ambiguous and `Short` is before `Byte`; `Any` against `String?` is ambiguous; of two equally specific candidates the one that uses fewer defaults is taken; a function type is taken before a `fun interface` for a Clojure function.
* An override and what it overrides are one member whatever their JVM names are (`override fun amt(): W`, a value class, is JVM `amt-<hash>` over `amt`): `ckway.meta` records the Kotlin override relation (`:overrides`: same name and parameter types, with the type arguments that the class gives its supertype), and a member that the class of the receiver overrides is no candidate. `(c/.amt (c/AmtImpl2))` is no longer "ambiguous". The result of a call that leaves a default out of such an override is boxed once.
* Generic overloads are ordered by inferring the type parameters of the less specific one from the other (`MutableList<T>.removeAll(predicate)` before `MutableIterable<T>.removeAll(predicate)`): `(kc/.removeAll (kc/mutableListOf 1 2 3) (fn [x] (= x 1)))` is no longer "ambiguous".
* A vector, map, set, keyword or var is passed as what it is before it is adapted as a function: `(kc/.removeAll ml [1 2])` is the `Collection` overload. A value that only the adapter can pass is adapted as before.
* For a Clojure function: a Kotlin function type, then a Kotlin `fun interface`; a Java functional interface only when every candidate has one.
* Hidden-deprecated declarations (`@Deprecated(level = HIDDEN)`, `@DeprecatedSinceKotlin(hiddenSince = ...)`) are no vars: `(ch/Channel)` is Kotlin's three-parameter factory, `(kc/.maxBy xs f)` is the one that Kotlin calls.
* Two candidates are not ordered on what a collection holds (the JVM erased it): a bounded type parameter at a type-argument position (`<T : Number> u9(a: MutableList<T>)` / `<T> u9(a: MutableCollection<T>)`) or one type variable for two invariant collections makes the call ambiguous, with the reason, the Java interop calls and `:<>` as the way out (`(p/u9 xs :<> Int)`); the type arguments of `:<>` are checked against the bounds in the choice.
* A Clojure persistent collection is read-only: a `Mutable*` parameter is a conversion for it, so `iv(x: Iterable<Int>)` is taken before `iv(x: MutableList<Int>)` for `[1]`, and `(kc/.asReversed [1 2 3])` is `List.asReversed`. With only a `Mutable*` candidate the call is made and a change throws `UnsupportedOperationException`.
* Declarations with `@Deprecated(level = ERROR)` (also by `@DeprecatedSinceKotlin(errorSince = ...)`) are no vars, as Kotlin refuses a call of them: `MutableList.sort(comparison)`, `String.toUpperCase()`, `appendln`.
